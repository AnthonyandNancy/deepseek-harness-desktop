# DeepSeek Harness 0.1.7-rc.1 升级实施方案（不移植上游 Desktop 端）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把本仓库从 `@deepseek-ai/dsh@0.1.5-rc.1` 升级到 `0.1.7-rc.1`，修掉唯一缺失依赖与两处上游破坏性变更，并让每日上游同步工作流与新的发布通道（`next`）对齐；**不引入上游 Desktop 端**。

**Architecture:** 本仓库是 Electron 宿主，不是 dsh 的 fork：运行时与 Web UI 一律来自已发布的 npm 包（`@deepseek-ai/dsh` + 随包 bundle `dsh-base` / `dsh-web-app`）。因此"升级"= 重钉依赖族 + 适配 CLI 契约；上游 Desktop 端不出现在本次范围内（理由见 Task 6 的决策记录）。

**Tech Stack:** Node.js 24（CI）、Electron 43.4.0、electron-builder 26.0.12、node:test、npm（`package-lock.json`）、NSIS。

## Global Constraints

- 依赖族一律**精确 pin**（无 `^`/`~`），且全部 `@deepseek-ai/dsh*` 必须同一条 release line；`scripts/sync-dsh-upstream.mjs` 会拒绝范围符与混线。
- 目标版本固定 `0.1.7-rc.1`；上游 tag `dsh-v0.1.7-rc.1`，commit `46a7f68b0922371ce7144b668b90e377d8e799f4`。
- 该版本位于 npm **`next`** 通道；`latest` 仍是 `0.1.5-rc.3`。禁止用 `npm run dsh:update`（走 `--latest`）做本次升级。
- 不引入上游 `apps/desktop` / `apps/desktop-host` 的任何代码或依赖；不改 profile 名（继续用 `web`）。
- 打包产物命名必须带被绑定的 dsh 版本段：`DeepSeek-Harness-Desktop-<desktop版本>-dsh-0.1.7-rc.1-<平台>-<arch>.<ext>`。
- 桌面端不 fork、不修改、不注入 Harness UI；扩展只走 profile patch 层与 Electron 宿主能力。
- Windows 必须保留 browse 目录选择器（禁用 native picker）。
- 所有验证命令都要在改动后真实执行；`npm test` 必须 0 fail。

Create `scripts/verify-dependency-closure.mjs`：

```js
#!/usr/bin/env node
/**
 * Guard against a half-landed runtime upgrade: the recorded upstream version and
 * the actually installed @deepseek-ai/dsh* tree must agree. Upstream ships every
 * @deepseek-ai/dsh package in lockstep and pins its family exactly, so any other
 * version means the install mixes two Harness builds. Verified against both the
 * 0.1.5-rc.1 and 0.1.7-rc.1 installed trees: zero packages of this family sit off
 * the release line, so this check needs no allowlist.
 */
import { readdirSync, readFileSync } from 'node:fs'
import path from 'node:path'
import { fileURLToPath } from 'node:url'

const root = path.resolve(path.dirname(fileURLToPath(import.meta.url)), '..')
const SCOPE = '@deepseek-ai'

export function collectPinViolations({ projectRoot = root } = {}) {
  const expected = JSON.parse(
    readFileSync(path.join(projectRoot, 'config', 'dsh-upstream.json'), 'utf8'),
  ).version
  const scopeRoot = path.join(projectRoot, 'node_modules', SCOPE)
  const violations = []

  for (const entry of readdirSync(scopeRoot, { withFileTypes: true })) {
    if (!entry.isDirectory() || !entry.name.startsWith('dsh')) continue
    let manifest
    try {
      manifest = JSON.parse(readFileSync(path.join(scopeRoot, entry.name, 'package.json'), 'utf8'))
    } catch {
      continue
    }
    const { name, version } = manifest
    if (typeof name !== 'string' || !name.startsWith('@deepseek-ai/dsh')) continue
    if (typeof version !== 'string' || version === expected) continue
    violations.push(`${name}@${version} (expected ${expected})`)
  }

  return violations.sort()
}

function isMainModule() {
  return process.argv[1] && path.resolve(process.argv[1]) === fileURLToPath(import.meta.url)
}

if (isMainModule()) {
  const violations = collectPinViolations()
  if (violations.length > 0) {
    console.error('Installed DeepSeek Harness packages drift from the pinned release line:')
    for (const line of violations) console.error(`  ${line}`)
    console.error('Run: npm ci')
    process.exitCode = 2
  } else {
    console.log('DeepSeek Harness install closure matches the pinned release line.')
  }
}
```

Create `docs/plans/desktop-port-decision.md`：

```markdown
# 决策记录：不同步上游 Desktop 端

- 状态：已采纳（2026-09-24，随 dsh 0.1.7-rc.1 升级）
- 范围：`@deepseek-ai/dsh` 升级到 0.1.7-rc.1 时，是否引入上游 `apps/desktop`

## 结论

不引入。本仓库继续作为基于已发布 npm 包的 Electron 宿主，profile 继续使用 `web`。

## 依据

1. 上游 Desktop 端不出现在 npm 上。`apps/desktop` 是 `@deepseek-ai/dsh-desktop@0.1.7-rc.1`，
   `"private": true`，依赖大量 workspace 私有包（`dsh-api-gateway`、`dsh-deepseek-account`、
   `dsh-agent`、`dsh-client-connection`、`dsh-host-webserver` 等），无法作为依赖取得。
2. 上游 Desktop 的构建链不属于本仓库能力范围：自带 Python/Node/pnpm 三段运行时
   （`prepare-primary-runtime`）、COS 产物上传、macOS 公证、Windows 硬件签名与 NSIS 深度定制。
3. `desktop` 这个 profile 名被上游 Electron 独占，CLI 会直接拒绝
   （`error: profile "desktop" is managed exclusively by the Electron application`），
   且 0.1.7 随包不提供 `desktop` profile 模板。本仓库没有等价实现，也不应伪造该名称。
4. 本项目的定位是"包装官方 Web 体验"（见 README 首段）：不 fork、不修改、不注入、不重新实现 UI。
   引入上游 Desktop 的 Electron 壳会改变项目性质，并与上游产生同名的第二实现，增加混淆与维护面。

## 影响

- 运行方式不变：Electron 以 `ELECTRON_RUN_AS_NODE` 启动 `@deepseek-ai/dsh/lib/bin.js --profile web`。
- Windows 继续使用 browse 目录选择器（`config/windows-directory-picker.patch.yml`）。
- 上游 Desktop 独有的能力（应用内浏览器 tab 的租约/分区桥、强制更新与崩溃恢复、账号内嵌页）
  在本项目中不提供；README 的 Known limitations 若受此影响则相应更新。
- 0.1.7 随包可获得的能力照常生效：agent preset 体系、`dsh-hmr` 配置热重载、
  "Open In..." 外部应用打开、Office 文档预览等。
```

## 风险与回滚

| 风险 | 触发条件 | 处置 |
|---|---|---|
| 旧安装残留原生模块 | 用户未退出托盘就覆盖安装 | 沿用 README 既有指引（托盘退出 → 卸载 → 重装）；Task 5 Step 4 在 PR 重申 |
| `dsh-code-runtime` 被别处引用 | 某 plugin 仍按旧包名解析 | 实测 0.1.7 全量闭包无该名、上游包目录已删除；若运行时报解析错误，改由 `dsh-ptc-runtime` / `dsh-ptc-runtime-node` 承载（均在 0.1.7 闭包内） |
| 上游再次移动路径打开实现 | 未来版本 | Task 4 的新逻辑识别不到 explorer 实现时**显式抛错**，不会静默放过 |
| pin 集与上游 bundle 漂移 | 上游新增直接依赖 | Task 3 的闭包守卫 + `npm run dsh:check` 双保险；新增包按 Task 1 Step 4 同法补 pin |
| 每日工作流继续误报 | 只做 Task 1 不做 Task 2 | Task 2 是本次升级的**必需项**：不做则 `latest`=0.1.5-rc.3 会被反复当作"更新"提 PR |
| 误用 `--latest` 手工升级 | 有人直接跑 `npm run dsh:update` | 该命令会判定"已是 0.1.5-rc.3 无需升级"或提旧版 pin；本文档与 PR 描述明确只走 `--version 0.1.7-rc.1` |
| 发布流程缺 Windows 准备步骤 | `release.yml` 的 windows job 不做 `prepare:windows`（只有 ci.yml 做） | 属既有行为（依赖 `npm ci` 的 postinstall 产物），本次不改；若 tag 构建产物缺 `dsh-node.exe`/启动器，按 ci.yml 补 `prepare:windows` 步骤处理 |

回滚：Task 1–4 各自独立成 commit，`git revert` 任一都能回到可用状态；`0.1.5-rc.1` 依赖族在 npm 上仍完整，可随时重钉。
